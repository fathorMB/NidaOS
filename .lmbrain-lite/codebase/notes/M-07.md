# Code notes: M-07

## 1. The installer is a new area without Anaconda.

core/internal/installer has the planner, the engine and the page server. The page is the second entry of the console project, thus it shares the tokens and the parts. Run quick-test.sh for the page in the demonstration mode.

Figure: 22 673 production lines

## 2. The plan uses the type of disk first, then the measured speed.

plan.go gives the system to the fastest disk. Two disks with a speed difference below 25% are the same speed: the smaller one gets the system. The VM test limits the speed of the virtual disks, thus the plan is the same in each run.

## 3. The engine erases only the disks of the plan.

engine.go runs wipefs and sgdisk only on the disks with a role. After bootc install, the root is read-only: the engine mounts it read-write again before it writes the plan and the first-boot file.

## 4. The first-boot file has the owner password until the first start.

firstboot.json is mode 0600 in /var/lib/nidaos. nida-core firstboot writes zeros on it and deletes it, also after an error. install.json on the seed volume also has the password: the operator keeps the seed volume safe.

## 5. The kiosk uses Firefox, not cog.

The Fedora package cog is a Python tool. cage starts Firefox in its kiosk mode with software rendering. A remote browser can only follow the installation: the server accepts the changes only from 127.0.0.1.
