# Code notes: M-05

## 1. M-05 adds about 3000 production lines in two new areas.

The new areas are runners (the controller, the job endpoint, the service) and the GitHub client in core/internal/github. The GitHub client uses only the standard library: the JWT signature is crypto/rsa, thus the core service has no new dependency.

Figure: 14 555 production lines

## 2. The job endpoint is the new security boundary.

The code of a workflow runs in the pod and talks only to this endpoint. The endpoint gives only the registry paths and the deploy of the app of the job token. Each change to this file needs a test in runners_test.go that examines an other app and an other path.

Figure: core/internal/runners/jobapi.go

## 3. The job endpoint uses plain HTTP on the pod bridge.

The job token goes in clear text on the bridge cni0 of the computer. Only the local pods use the bridge, and each token is valid for one pod only. M-11 can add TLS with a certificate of the NidaOS authority for this address.

Figure: 10.42.0.1:8471

## 4. The BuildKit sidecar needs the seccomp profile Unconfined.

Rootless BuildKit makes a user namespace, thus the namespace nida-runners has the privileged pod security level. No container is privileged and all run as normal users, but a weakness of the kernel is easier to use from this pod. Examine a newer BuildKit mode at each update of the image.

Figure: core/internal/runners/manifests.go

## 5. The controller depends on the GitHub API rate limit.

With no queued job, the controller reads one list of runs for each connected repository. This is 240 calls an hour for each repository, and the limit is 5000 for the installation. With more than about 15 repositories, make the poll interval longer.

Figure: 1 call each 15 seconds per repository

## 6. The VM test now needs two secrets and the network of GitHub.

The runs of this milestone failed four times before the VM, because the DNS server of the runner did not resolve ubuntu.com. The workflow now uses the main archive and public DNS servers. Without the secrets of the test app, the test skips the GitHub flow.

Figure: 109 checks
