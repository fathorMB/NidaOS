# Code notes: M-06

## 1. The web console is the largest new area.

M-06 adds the console in TypeScript: the frame, nine pages, the live store and the shared parts. The pages use only the API of docs/api.md, thus a change of the API must also change console/src/api.ts.

Figure: 19 803 production lines

## 2. The app page is the largest file of the console.

console/src/pages/apps.tsx has the list, the six tabs and the form. If it grows in M-09 or M-10, divide it into one file for each tab.

## 3. One store feeds the live data of all the pages.

live.tsx opens one stream of metrics and one of logs. A page does not open its own stream. The unit tests examine the stop of a stream, and the VM browser test examines the banner.

## 4. The browser tests run against the VM and against a fake API.

console/dev/mock.mjs gives sample data for the development on Windows. Keep it the same as docs/api.md, or the tests against the fake API do not find the problems of the real API.

Figure: 7 browser tests

## 5. The updates API only calls bootc.

core/internal/updates runs bootc status, upgrade, rollback and the restart, one at a time, with the admin level (D31). M-11 adds the automatic checks and the signatures of the images.

## 6. Traefik sends the console requests to nida-core on the pod bridge.

core/internal/apps/console.go makes a Service without a selector and an EndpointSlice to 10.42.0.1:8470. The login limiter trusts X-Forwarded-For only from the pod network. An app pod can also open this address, thus the API keeps its own sign-in.
