# Code notes: M-04

## 1. The product code grew from 8505 to 11535 lines.

M-04 adds the database controller, the links, the backups, the restore and the updates. Most of it comes from GitStack core. It has no new external dependency: the exec into the pods uses client-go.

Figure: 11535 lines

## 2. The tests grew from 106 to 135 test cases.

The unit tests use a fake cluster, a fake psql and a fake pod. They cannot run PostgreSQL. The VM test adds 21 checks on a real server, thus each change of the SQL or of pg_hba.conf needs the VM test too.

Figure: 135 tests

## 3. The database controller is the largest file of the area.

core/internal/databases/controller.go makes the server, waits for it and syncs the objects. The links, the backups, the restore and the updates are in separate files of the same package.

Figure: 461 lines

## 4. The backups have all the data and no encryption.

The pg_dump files are in /var/nida/standard/backups with the mode 0600, on the same computer as the databases. A failure of the computer loses the databases and the backups together. M-11 must add the encryption and a copy to an other computer.

## 5. The VM test step takes about 16 minutes.

scripts/vm-test.sh now examines M-01 to M-04 in one run. The limit of 30 minutes in knowledge/testing.md is still enough, but each new milestone adds time.

Figure: 16 minutes
