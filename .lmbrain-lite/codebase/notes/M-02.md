# Code notes: M-02

## 1. The core service has 4679 lines of product code.

M-02 adds all the Go code of nida-core and the nida command. The code uses only the standard library of Go, thus it has no external dependency to update.

Figure: 4679 lines

## 2. The tests have 2494 lines and 74 test cases.

The tests run on Windows and on Linux in CI. The VM test adds 38 checks on the real image. Keep a test for each new path of the API.

Figure: 74 tests

## 3. The API area holds the access rules of all the paths.

core/internal/httpserver/auth.go decides the access of each path. A new path gets the default rule: read for GET, admin for the other methods. Examine this file for each new path.

## 4. The log store is the largest source file.

core/internal/logs/store.go writes, rotates, compresses and searches the log files. A change to its file format must keep the old days readable for 30 days. This snapshot has no complexity data for the functions.

Figure: 449 lines

## 5. The VM test script changes with the image.

scripts/vm-test.sh changed in most commits of T-08. Follow the rules in knowledge/testing.md for each change: quote the ssh commands as one string and give curl a time limit.
