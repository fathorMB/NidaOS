# Code notes: M-03

## 1. The product code grew from 4679 to 8505 lines.

M-03 adds the app hosting, the certificate authority and the mDNS responder. The core service now uses client-go of Kubernetes (decision D22), thus it has external dependencies to update for the first time.

Figure: 8505 lines

## 2. The tests grew from 74 to 106 test cases.

The app tests use a fake cluster of client-go. The VM test adds 26 checks on the real k3s. The fake cluster does not run the rollouts, thus each change of the deploy logic needs the VM test too.

Figure: 106 tests

## 3. The app controller is the largest file of the hosting area.

core/internal/apps/controller.go applies the versions, waits for the health check and goes back to the version before. It comes from GitStack core. A fix in GitStack can apply here too.

Figure: 734 lines

## 4. The app store keeps the secrets in a JSON file.

core/internal/apps/store.go writes the apps and the secrets in /var/lib/nidaos/apps.json with the mode 0600. A backup of this file has the secrets: M-11 must encrypt it or keep it out of the backups.

## 5. The VM test script grew with each milestone.

scripts/vm-test.sh now examines M-01, M-02 and M-03 in one VM step of about 14 minutes. A separate function file for each milestone can make the failures easier to find.

Figure: 14 minutes
