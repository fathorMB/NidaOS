# M-05 — GitHub runners and the deploy flow

## Outcome

A push to a GitHub repository builds the app on NidaOS and puts it in operation. The source stays on GitHub.

## Tasks

- [ ] T-01 Run a GitHub self-hosted runner on NidaOS in a container with limits
- [ ] T-02 Add and remove a runner from the API, with a registration token from GitHub
- [ ] T-03 Build the app image on the computer and keep it in a local registry
- [ ] T-04 Write the nida app deploy command that the workflow calls
- [ ] T-05 Make the pull request that adds the deploy workflow to a repository
- [ ] T-06 Show each deploy job with its log in the list of deploys
- [ ] T-07 Test the flow from a push to an app in operation with a real GitHub repository
- [ ] T-08 Make the GitHub App of NidaOS with the manifest flow, and import an app for the tests
- [ ] T-09 Give the runner pods a job endpoint for the registry and the deploy, with a token for one job
